# Native global shortcuts

[LUNE-379](https://linear.app/nouvelle-lune-atelier/issue/LUNE-379/add-configurable-global-media-shortcuts) adds an optional global shortcut service. Open **Settings → Global Shortcuts**, edit individual combinations with **Apply** or **Clear**, then enable registration. **Reset defaults** restores the suggested combinations. The feature is disabled initially; while disabled it creates no native registrations, D-Bus connections, polling threads or keyboard hooks.

Actions cover play/pause, explicit play/pause/stop, previous/next, five-second seeking, volume, mute, ratings, shuffle and repeat. They call the same player, shell and library commands as the main window. Ratings retain connection and mutation-busy guards. The normal in-window shortcuts remain available. Global commands also respect the app's focused text field, modal dialog and menu guards. Other applications do not prevent enabled global commands from reaching this app.

## Configuration and feedback

A binding is one chord using letters, digits, arrows/navigation keys, F1–F24 or supported Media keys. Modifiers are Ctrl, Alt, Shift and Meta (Command on macOS, Super on Linux). Ordinary character keys require Ctrl, Alt or Meta. Duplicate bindings, known reserved desktop combinations and native registration failures appear beside the affected action. Accepted registrations remain active when another action fails. Retry registration after resolving a desktop conflict or changing a macOS keyboard layout.

Preferences contain only bindings and the opt-in flag. Invalid saved data disables registration. Disabling or quitting releases registrations and sessions; changing preferences invalidates old callbacks. Worker results and key activations are delivered to the Qt GUI thread before changing playback.

## Platform adapters

- **Linux, including Wayland:** uses the XDG GlobalShortcuts portal over the existing Jeepney dependency. Permission and D-Bus waits run in a worker thread. The desktop chooses accepted combinations, which are displayed as **Active** values; its selection may differ from the requested combination. Portal version 2 exposes **Desktop shortcuts…**. Changes from that UI update the displayed bindings. Denied/cancelled permission, missing portals and closed sessions show retryable status while existing MPRIS controls remain available. Requests/session handles are closed on cancellation and shutdown. No compositor-specific keyboard grab is installed. See the [portal interface](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.GlobalShortcuts.html) and [trigger specification](https://specifications.freedesktop.org/shortcuts/latest/).
- **Windows:** uses `RegisterHotKey` with `MOD_NOREPEAT` and Qt's native event filter for `WM_HOTKEY`. Windows-key combinations and F12 are rejected as reserved. Windows registration failures are shown per action. Media Play/Pause aliases map to the OS toggle key, so duplicate physical keys are detected too. See [Microsoft's registration reference](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey).
- **macOS:** uses Carbon `RegisterEventHotKey` with active keyboard-layout translation. Unsupported keys, including Media keys unavailable through this API, produce per-action feedback. Input monitoring and a general key-event tap are not requested. Character/byte counts use Apple's native `unsigned long` ABI. Registration can differ by macOS release and system bindings; failures remain visible. See [Apple's 64-bit type guide](https://developer.apple.com/library/archive/documentation/Carbon/Conceptual/Carbon64BitGuide/PortingTo64Bit/PortingTo64Bit.html) and [Apple's hotkey compatibility discussion](https://developer.apple.com/forums/thread/763878).

## Verification and remaining platform gates

Unit checks cover normalization, duplicate/reserved bindings, invalid saved preferences, disabled inactivity, registration replacement, stale callbacks, focused-window guards, all shared commands and GUI-thread delivery. Native API fakes cover Windows/macOS key mappings, registration errors, event dispatch and cleanup. Portal protocol fakes cover early responses, permission denial, unavailable services, session-scoped events, partial binding updates and cancellation. An actual Qt window checks enabling, editing/error display, narrow settings layout, text/modal isolation and unchanged local Space behavior.

The Linux development host reports KDE GlobalShortcuts portal version 2 in a read-only capability probe. This does **not** establish successful permission approval or physical global-key delivery. Verify those on KDE/Wayland and another supported desktop. Windows/macOS hardware key delivery, keyboard-layout changes, desktop conflicts and packaged application behavior remain acceptance work under the existing LUNE-351/LUNE-352 platform tickets. These shortcuts do not claim completion of taskbar, Touch Bar or other platform media-control work.
